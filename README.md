# Limits AI

Отслеживание лимитов ИИ-сервисов. В репозитории два приложения:

- **Android** (`android/`) — сам определяет расход лимитов Claude и ChatGPT/Codex по вашему аккаунту.
- **PWA** (`app/`) — ручной учёт для любых сервисов: https://andreyroyal.github.io/Limits-AI/

## Android: автоматическое определение

Скачать последнюю версию: https://github.com/ANDREYROYAL/Limits-AI/releases/latest/download/limits-ai.apk
(на телефоне разрешите установку из браузера).

Как работает:

1. В приложении нажимаете «Войти в Claude» или «Войти в ChatGPT / Codex» и входите на сайт сервиса во встроенном браузере.
2. Приложение открывает в невидимом WebView те же адреса, которые использует сам сайт, под вашим входом:
   - Claude: `claude.ai/api/organizations` → `claude.ai/api/organizations/{id}/usage` —
     сессия (5 ч), неделя и недельные лимиты по моделям, в процентах и со временем сброса;
   - ChatGPT / Codex: `chatgpt.com/api/auth/session` → `chatgpt.com/backend-api/wham/usage` —
     окна Codex (5 ч и неделя), тот же источник, что у команды `/status` в Codex CLI.
3. В фоне данные обновляются каждые 15/30/60 минут (WorkManager). Уведомления приходят при 80 %,
   при исчерпании лимита и когда он восстановился.

Ограничения:

- Эти адреса — внутренние, не публичное API. Если сервис их поменяет, приложение покажет
  «Сервис ответил в неожиданном формате», и разбор надо будет обновить (`android/core/.../Parsers.kt`).
- Вход через Google во встроенном браузере Google может не пустить. Используйте вход по почте.
- Лимиты обычных чатов ChatGPT (сообщения моделям в Plus) сервис не отдаёт — видны только лимиты Codex.
- Данные и вход хранятся только на телефоне.

Сборка: GitHub Actions (`.github/workflows/android.yml`) прогоняет тесты, собирает APK и
при пуше в `main` публикует его релизом. Локально — Android Studio или `cd android && ./gradlew :app:assembleRelease`.
Тесты разбора без Android SDK: `cd android && CORE_ONLY=1 ./gradlew :core:test`.

## PWA: ручной учёт

### Возможности

- Пресеты популярных сервисов. Все параметры можно менять, лимит запросов указывать необязательно.
- Пять типов сброса:
  - **окно от первого запроса**: окно на N часов открывается первым запросом (как 5-часовая сессия Claude);
  - **скользящее окно**: каждый запрос «сгорает» через N часов;
  - **каждый день / неделю / месяц** в заданное время.
- Кнопка «Лимит кончился» с точным временем восстановления, которое показал сервис (или расчётным).
- Обратный отсчёт до сброса и уведомление, когда лимит восстановлен.
- Работает офлайн и ставится на телефон как приложение: в Chrome нажмите «Добавить на главный экран».
- Данные хранятся только на устройстве (`localStorage`). Для бэкапа и переноса есть экспорт и импорт в JSON.

Ограничение: браузер не умеет показывать уведомление по расписанию, когда приложение полностью закрыто.
Уведомления приходят, пока приложение открыто или свёрнуто в фоне.

### Разработка

Сборки нет, это обычные HTML/CSS/JS-модули в папке `app/`.

```bash
cd app && python3 -m http.server 8000
```

```bash
npm test
```

Тесты логики PWA лежат в `tests/`, запускаются встроенным `node --test`.

### Публикация

Workflow `.github/workflows/pages.yml` при пуше в `main` прогоняет тесты и публикует папку `app/` на GitHub Pages.
Один раз включите: **Settings → Pages → Source: GitHub Actions**.
